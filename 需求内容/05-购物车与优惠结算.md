# 购物车与优惠结算

> 来源：原文档 §3.4 购物车与结算模块（§3.4.1 购物车管理、§3.4.2 订单结算）、附录 A「选择优惠方式」弹窗

## 1. 模块范围

**包含：** 购物车商品管理（含数量调节）、订单结算页优惠互斥逻辑、活动优惠与优惠券的二选一机制、智能推荐、二次确认、"选择优惠方式"弹窗完整交互设计。

**不包含：** 支付流程（原文未涉及）、订单创建后状态流转（见 `06-个人中心.md`）、活动类型与优惠券类型定义（见 `08-后台运营管理.md`）。

> **聚合说明**：本文件将 §3.3.2 弹窗触发条件、§3.4.2 互斥规则、附录A 弹窗交互详设三处来源聚合，是系统最核心的业务规则模块。

## 2. 业务流程

### 2.1 购物车管理流程

```
商品详情页 → 加入购物车 → 购物车列表
    → 调节数量（+/-、手动输入）
    → 删除商品（数量减至1以下时触发）
    → 选中商品 → 进入结算
```

### 2.2 订单结算——优惠互斥核心流程

```
进入结算页 → 系统计算最优方案（比较活动优惠 vs 优惠券优惠金额）
    → 默认勾选省钱最多的方案
    → 用户可见两个互斥板块：
        ├── [活动优惠区] — 可选各活动/原价
        └── [优惠券区]   — 可选各优惠券
    → 两个板块互斥：选中一个则另一个置灰
    → 用户可切换选择（活动→券需二次确认）
    → 确认选择 → 继续下单
```

### 2.3 "选择优惠方式"弹窗交互流程（附录A 完整流程）

```
触发条件满足 → 弹窗展示
    → 系统计算最优方案 → 默认选中更优方
    → 另一方置灰（opacity 0.5，不可点击）
    ├── 用户点击置灰方 → 二次确认 → [继续]切换 / [取消]保持
    ├── 用户在活动区内切换 Radio 选项 → 实时生效
    └── 用户点击[确认选择] → 关闭弹窗，应用选择
```

## 5. 异常、边界和验收标准

### 5.1 原文明确的验收标准

| 编号 | 内容 | 来源 |
|---|---|---|
| CK-A01 | 活动与优惠券不可叠加，选择一方则另一方置灰 | §3.4.2 CK-006 |
| CK-A02 | 从活动切换到优惠券须二次确认 | §3.4.2 CK-010 |
| CK-A03 | 从优惠券切换到活动无需二次确认 | 附录A §3 CK-015 |
| CK-A04 | 购物车非法值自动修正并 Toast 提示 | §3.4.1 CK-003 |

### 5.2 隐含边界（测试关注点）

| 场景 | 测试关注点 |
|---|---|
| 活动优惠 = 优惠券优惠（金额相同） | 智能推荐默认选中哪一方？ |
| 用户选择"不参与活动，按原价购买" | 优惠券区是否仍可用？ |
| 弹窗中点击 X 关闭按钮（不点确认） | 购物车/购买操作是否取消？ |
| 购物车商品库存变化（小于购物车数量） | 是否自动修正？ |
| 购物车商品下架/活动结束 | 商品处理？标签变化？ |
| 结算时活动/优惠券刚结束/过期（并发） | 如何处理？ |
| 弹窗中活动区多项切换后再次切回 | 是否仍需二次确认？ |
