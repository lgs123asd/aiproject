## 2. 业务流程

原文未提供端到端总体业务流程图。以下从功能架构推导核心流程：

```
用户进入 → 登录/注册 → 首页浏览 → 商品搜索/筛选
    → 商品详情（选择优惠方式[如有多活动冲突]）
    → 加入购物车 → 购物车管理 → 订单结算（活动 vs 优惠券互斥选择）
    → 支付 → 订单状态流转（待付款→待发货→待收货→待评价→已完成）
    → 积分发放（订单完成后）
    → 积分商城兑换
```

后台运营独立流程：
```
运营登录后台 → 活动配置（秒杀/满减/满赠/聚划算）
    → 优惠券配置（商品券/订单券）
    → 首页模块配置（显隐/排序）
    → 商品管理
```

## 3. 功能规则

| 规则编号 | 规则内容 | 来源 |
|---|---|---|
| OV-001 | 系统需支持运营后台动态配置活动与优惠券，无需代码发布即可上线营销活动 | §1.2 灵活性 |
| OV-002 | 系统需严格隔离"活动优惠"与"优惠券"，杜绝资损风险 | §1.2 严谨性 |
| OV-003 | 全链路支持商品数量快速调节 | §1.2 体验优化 |
| OV-004 | 前端采用 Vue.js/React SPA 应用 | §2.1 系统架构 |
| OV-005 | 后端为微服务架构，包含独立的「促销计算引擎」处理互斥逻辑与价格计算 | §2.1 系统架构 |
| OV-006 | MySQL 存储业务数据，Redis 缓存活动库存、会话信息及热点数据 | §2.1 系统架构 |
| OV-007 | 系统分用户端（登录、首页、商品中心、购物车、个人中心、积分商城）、运营端（活动管理、优惠券管理、商品管理、用户管理）、核心逻辑（优惠互斥锁、积分结算、库存扣减、安全风控）三大板块 | §2.2 功能架构图 |
